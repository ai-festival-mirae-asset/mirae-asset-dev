# mirae-asset-dev · `papuagigi` 브랜치

미래에셋 AI Festival 금융상품 에이전트 개발 — 개인 작업 브랜치.

이 브랜치는 **main과 분리해서** 각자 만든 것을 담는다. 팀 공동 문서(`PROJECT_GUIDE.md`)와 대회 원본 데이터(`datasets/`)는 이 브랜치에 두지 않는다. 각자 어느 정도 만든 뒤, 필요한 것만 골라 main으로 합친다.

## 폴더 구조

```
├── 전처리/                        ── 제공 데이터를 다루기 위한 작업
│   ├── 데이터_전처리_방법.md         ▸ 무엇을·왜 이렇게 처리했는지 (먼저 읽을 것)
│   ├── preprocess.py                ▸ 전처리 스크립트 (재실행 가능)
│   ├── 처리결과/                    ▸ 전처리된 CSV 4종 + 격리 행 + 규칙 리포트
│   └── 프로파일링/                  ▸ 전처리 이전의 실태 조사 (결측률·고유값 실측)
│
├── 외부데이터/                     ── 제공 데이터를 해석하기 위한 자료
│   ├── 외부데이터_수집_방법.md       ▸ 무엇을·왜·어디서 수집했는지 (먼저 읽을 것)
│   ├── 수집_요약.md                 ▸ 수집 결과 요약 + 8/6 설명회 질문 리스트
│   ├── 사전/                        ▸ 컬럼·값·별칭·등급·코드·지수 사전 9종
│   └── _원본/                       ▸ 리서치 원본 JSON (출처·재현용)
│
├── memory.md                     연속 작업 기록
└── 금융상품Agent_프로젝트_로드맵.md   전략 로드맵 (개인 브랜치 관점)
```

## 실행 방법

원본 xlsx 8개(대회 제공)는 저장소에 없다. **참가자 전원이 이미 가지고 있으므로 커밋하지 않는다.**

**1) 원본 데이터 위치 지정** — 둘 중 하나

- repo 루트에 `datasets/` 폴더를 만들고 xlsx 8개를 넣는다 (기본값, `.gitignore` 처리됨)
- 또는 데이터를 다른 곳에 두고 환경변수로 알려준다

```bash
export MIRAE_DATASETS="/path/to/금융상품"
```

**2) 전처리 실행**

```bash
python 전처리/preprocess.py
```

`전처리/처리결과/`에 전처리 CSV 4종이 생성된다. 같은 입력이면 항상 같은 출력(멱등)이라 몇 번 돌려도 안전하다.

**3) 원본 실태 조사 (선택)**

```bash
python 전처리/프로파일링/profile_data.py
```

## main 브랜치에 있는 것

이 브랜치에서 지웠지만 필요하면 언제든 꺼내 볼 수 있다.

| 대상 | 꺼내는 법 |
|---|---|
| 팀 공동 실행 가이드 | `git show main:PROJECT_GUIDE.md` |
| 원본 데이터 | `git show main:datasets/...` 또는 대회 제공 파일 사용 |
| Lance manifest | `git show main:manifest/2.manifest` (fragment 누락으로 사용 불가) |
