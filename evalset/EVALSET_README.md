## 3. 설계 원칙 (문항이 이렇게 만들어진 이유)

1. **전 문항 실측 grounding.** 등장하는 상품명·종목명·수치는 전부 8/13까지 실데이터에서 확인된 것만 사용(TIGER 200, 캠브리콘 16종목, 삼성전자 229종목, 빈 PDF 7종목 등). 존재가 불확실한 이름은 쓰지 않았다 — 대신 모집단 질의(필터·정렬)로 표현.
2. **gold는 값이 아니라 질의 스펙.** 데이터가 재수집·정정되면 값이 변하므로, 러너가 스펙을 실행해 기대값을 동적으로 산출한다(예: "pd_net_tamt 내림차순 5"). 고정 수치는 실측 검증된 것만 병기.
3. **유형 예시의 일반화(8/13 사용자 확인).** 공식 예시는 실제 문항이 아니라 유형 예시 — 캠브리콘·에코프로 같은 특정 개체 변형과 함께 동일 유형의 다른 개체(엔비디아·구글·SK하이닉스·리츠) 문항을 배치해 과적합을 방지.
4. **behavior 3분법이 핵심 채점축.** 실전 감점 구조(트랩에 답하면 감점, 데이터 없는데 지어내면 오답)를 미러링 — `refuse`가 정답인 문항(트랩 15 + M-29)과 `partial`(커버리지 명시 없으면 실패) 문항을 의도적으로 섞음.
5. **데이터 함정을 문항화.** 총보수 결측 87.5%(L-26·H-03·H-30), 해외 위험등급 부재(M-29·T-13·H-13), 펀드 마스터/클래스 구분(L-21), ETF/ETN 혼재(L-11·L-13), 잔존만기 재계산(L-04·H-26), 빈 구성 공시(M-19·H-19), 운용사 오염 55행(M-09·H-29), 우선주 구분(M-16) — ROADMAP §5의 함정 전부가 최소 1문항에 걸려 있다.
6. **트랩 5유형 × 3변형**: 값 도메인 밖(T-01~03) / 미존재 개체(T-04~06) / 미존재 상품(T-07~09) / 시점 위반(T-10~12) / 데이터에 없는 필드(T-13~15). 트랩 방어 정책(직접 매칭만·간접 연상 금지)은 §10 참조.

## 4. 자동 채점기 (= 구현 순서 ⑦, 8/18 완성 — `eval_runner.py`)

```bash
python evalset/eval_runner.py                    # 실전 구성(그래프 전체·벡터·HCX) — 서버와 같은 부품을 직접 호출
python evalset/eval_runner.py --no-hcx --kg kr_etf,constituents   # HCX 끄고(크레딧 0) 규칙·그래프·벡터만
python evalset/eval_runner.py --light           # 규칙 엔진만
python evalset/eval_runner.py --mode http --base-url http://127.0.0.1:8000    # 켜져 있는 서버에 HTTP 로(원격 리허설)
python evalset/eval_runner.py --ids T-04,L-11 --baseline evalset/reports/이전.jsonl
```

1. 문항별 실행: 서버와 같은 `answer_question` 경로(요청별 시간 예산 포함) 또는 `GET /answer` → 응답 5필드 + 응답 시간(내부 목표 15초 — 주최는 기준을 공개하지 않음(8/26 공지) / 문서 권장 60초 / 하드 300초 — "15초 초과"를 위험 지표로 본다)
2. 채점 4축: ① **태도 일치** — refuse 문항에 목록(`결과 N건`·번호 매긴 줄 2개 이상)을 내면 **함정 오답**(최우선 집계), 정상 문항 거절은 **과잉 거절**, partial 문항은 한계 문구 필수 ② **근거 표시**(근거 블록의 출처·기준일 + 답변 안 기준일) ③ **내용 검사**(`checks_v1.jsonl`, 기대값은 SQL 로 계산) ④ **응답 시간**. **종합 통과 = ①O + ②O + ③(검사 있으면)O**
3. 성적표: 한 줄 요약 → 난이도별 표 → 거절 문항 16개 표 → 종합 미통과 문항 상세(실패 축·답변 발췌) → 응답 시간 상위 → 채점 범위 안내. `--baseline` 으로 이전 실행과 비교
4. 채점기 자체 검증(`tests/test_eval_runner.py`): 가짜 답변으로 판정 규칙 잠금(거절문 뒤에 목록을 숨긴 답변도 함정 오답으로 잡는지 등) + 실제 시스템의 거절 정답 16문항이 전부 '거절 정답'으로 읽히는지 + 검사표 SQL 전부 실행 가능한지
5. 한계: 내용 검사의 기대값을 우리 SQL 로 계산하므로 SQL 자체의 오류는 못 잡는다 → 성적표의 답변 발췌를 사람이 함께 본다. 주최 문의(트랩 vs 수집 데이터) 답변 수신 시 T-04 계열 gold 재확정. 8/18 공식 자료의 답변 불가 정답 기준("확인할 수 없음" 명시 **또는 필요한 조건 역질문")은 behavior=refuse 판정에 반영
6. **성적표 이력(실전 구성 = 그래프 전체·벡터·HCX)**: 8/19 10:45 **80/105**(첫 성적표) → ⑧ 다듬기 후 8/19 12:33 **96/105** → 2차 보정 후 `reports/` 최신 `_full` 참조. HCX 없이(규칙·그래프·벡터만)는 87 → 105/105. **같은 코드로 두 번 돌리면 HCX 문장 변동으로 ±2~3문항 흔들릴 수 있다** — 온도 0.2·seed 고정(8/19)으로 줄였지만 0 은 아니다. 규칙 변경의 회귀는 `--no-hcx` 로(결정적, 크레딧 0), HCX 경로 변경은 실전 구성으로 확인한다. 사후 대조가 지운 줄은 `think_trace` 의 `생성:` 줄에 이유와 함께 남는다(8/19) — 과잉 삭제 진단용
7. **H-13 정답 기준(8/19 정정)**: 국내 채권은 위험등급(PD_RISK_GCD 1~6) 집계에 **포함**한다(공식 자료 p.5 '신용·위험등급', 데이터 실측) — 옛 gold 의 "채권은 등급 체계 상이" 해석은 폐기(팀원 8/18 반영과 일치)
