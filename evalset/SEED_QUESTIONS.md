**트랩 방어 정책 — "수집 데이터에 관련 정보가 있으면?" (8/13 논의, 주최 문의 접수됨 — 답변 대기):**

1. **답변 가능한 상품 모집단은 제공 4종 마스터로 고정한다.** 외부 수집물(구성종목 등)은 상품의 *속성*을 보강할 뿐, 상품 유니버스를 확장하지 않는다 — "kimi 관련 **상품**"의 후보군은 수집과 무관하게 불변.
2. **"관련" 판정은 직접 개체 매칭만.** 질의 엔티티가 데이터의 개체(상품명·구성종목명·운용사명·지수명·별칭 사전)와 명시적으로 일치할 때만 관련으로 본다. **간접 연상 체인 금지**(예: "kimi는 Moonshot AI 챗봇 → 투자사 알리바바 → 알리바바 편입 ETF" — LLM 사전지식 기반 확장은 트랩 감점 경로다).
3. **부분 문자열 주의**: 별칭·이름 매칭은 단어 경계·전체 명칭 기준으로. (가상의 예: "KIMIA FARMA" 같은 무관 종목이 "kimi" substring 에 걸리면 오답 — 현 데이터엔 없음을 실측했으나 일반 규칙으로 채택)
4. 만약 질의 엔티티가 **구성종목에 실존**하면(캠브리콘처럼) 그건 트랩이 아니라 정상 질의 — "직접 매칭 존재 여부"가 두 케이스를 가른다.
5. 주최 측 답변(사용자 문의) 수신 시 이 정책을 재확정한다.

## 2. 예시가 말해주는 것 (설계 시사점)

1. **하 난이도만 제공 RDB로 풀린다.** 중·상 4문항 전부가 구성종목(국내+해외)·기업 관계·비정형 서술 중 최소 하나를 요구 — "비정형 수집이 과제의 핵심"(8/6 발언)이 예시로 재확인됨.
2. **해외ETF 구성종목 "유형"이 출제 범위다**(중-2). 예시가 유형 예시이므로 캠브리콘 한 건이 아니라 **해외 구성종목 일반**이 필요 — 국내(KRX)만으로는 중 난이도부터 구멍.
3. **"현재/최근 N개월"은 전부 기준일(2026-07-11) 앵커로 해석** — time_policy·Answer Validation의 시간 규칙에 반영.
4. 상 난이도는 **채널 3개 조합**(그래프+SQL+벡터)이 기본형 — Query Router가 없으면 못 푼다.
5. 답변 불가 3종은 유형이 서로 다르다: 값 도메인 위반(T-1) / 존재하지 않는 개체(T-2) / 존재하지 않는 상품명(T-3) — Answer Validation이 세 검증을 각각 갖춰야 한다.
