## 2. 해석 사전 9종 (2026-08-04)

### 2-1. 왜 이 데이터들인가

제공 데이터의 해석 난이도가 상품군마다 극단적으로 다르다.

- **국내채권**: 스키마에 한글 컬럼명이 하나도 없다. `DUR`, `COV`, `DIRTY`, `NDY_APPLIED_YIELD`, `DEPO_EQUIV_YIELD_154` 같은 약어 40개를 해석하지 못하면 테이블 전체를 못 쓴다.
- **해외ETF**: 한글명 없음 + 기초지수가 Lipper 영문 표기(수익률 유형 접미어 TR/PR/NR/CR 포함).
- **사용자 질의는 데이터의 언어로 오지 않는다**: "타이거 미국S&P500"(브랜드 별칭), "곱버스"(은어), "AA급 이상"(등급 표현), "KBSTAR ETF"(2024년에 RISE로 리브랜딩된 구명).
- **등급·코드는 서열과 체계가 필요하다**: "신용등급 AA 이상" 필터는 등급 서열표(AAA=1~D=20)가 있어야 SQL이 된다.

선정 기준은 하나 — **"이게 없으면 어떤 질의가 틀리는가?"**

### 2-2. 어떻게 수집했나 (3단계)

```
① 실측 (내부)          ② 웹 리서치 (외부)         ③ 적대적 검증
xlsx 4쌍 전수 스캔   →   8개 도메인 병렬 리서치   →   오류 위험 상위 3개 도메인
- 207개 컬럼 스키마      - 전 항목 출처 URL 필수      (채권약어·신용등급·별칭)
- 범주형 고유값 423행    - 확인 불가 시 low 표기      - 반박 시도 → 13건 정정
```

①이 ②를 결정한다: 데이터에 실제로 존재하는 값(예: `CRD_GRD`의 'AA0', BD_KND의 'Conduit회사채', 브랜드 접두어 'N2', '1Q')만 조사했다. 그래서 사전의 모든 항목이 데이터의 실제 값과 1:1로 연결된다. 출처는 공식·1차 출처 우선(금융투자협회·KRX·금융감독원 규정, 신용평가 3사 등급 정의 원문, 운용사 공식 사이트, ISO 표준). **웹에서 확인 못 한 추정은 `confidence=low`로 정직하게 표기**했다 — 그럴듯한 추정을 high로 위장하는 것이 사전의 최악 오염이기 때문이다.

### 2-4. 대표 수확과 정정

- `DEPO_EQUIV_YIELD_154`의 **154 = 이자소득세율 15.4%** → "예금환산수익률"(증권사 화면 각주로 확인). `DUR`=듀레이션, `COV`=컨벡시티, `DIRTY`=경과이자 포함 가격, `EVAL_PRICE`=민평가격. `NDY_*` 5종은 "익일 적용 민평값"으로 **추정**(공식 정의 미확보 → low).
- `CRD_GRD`의 "AA0" = 무부호(플랫) 표기 → 끝자리 0 제거로 정규화, 서열 AAA=1~D=20. 질의 변환은 이후 확정된 해석([PLAN.md](../PLAN.md) §5 8/14·8/26)을 따른다 — "AA 이상"은 문자 그대로, "AA급" 단독은 AA+·AA·AA- 묶음.
- 리브랜딩 연표(구명 질의 대응 필수): KINDEX→ACE(2022-10), SMART→SOL(2021-08, 검증에서 9월→8월 정정), KBSTAR→RISE(2024-07), ARIRANG→PLUS(2024-07), KOSEF·히어로즈→KIWOOM(2025-01), KTOP→1Q(2024-04), QV→N2(2024-06, ETN), MASTER→KCGI(2024), ITF→IBK(2026-05).
- 국내ETF 파일의 ETN 혼동 페어: KODEX(삼성자산운용) vs 삼성 ETN(삼성증권), TIGER(미래에셋자산운용) vs 미래에셋 ETN(미래에셋증권) 등 — 미래에셋 계열 3주체(TIGER=미래에셋자산운용 / '미래에셋 ○○ ETN'=미래에셋증권 / Global X=해외 자회사) 구분.
- 해외: iShares=BlackRock, SPDR=SSGA, Direxion=Rafferty, Xtrackers=DBX 등 법인명↔브랜드 매핑.
- KOFIA 20자리 펀드코드 **6번째 자리 = 클래스 유형**(금투협 공식 Q&A로 확인).
- 해외ETF 기초지수 "Index is not provided by Management Company" 류 센티널 2종 = **실질결측 48%** → 전처리 규칙의 근거. 국내ETF `pd_pen_risk_nm` 위험자산 788 + 안전자산 214 = 1,002 = 퇴직연금 거래 가능(Y) 건수와 정확히 일치 → 'N' = 연금거래불가로 확정.
- 적대적 검증 정정 13건: 채권 용어 7(평가사 "4사"→금투협 등재 5개사, NDY 추정 하향, 세금우대저축 폐지 반영) · 신용등급 2(서울신용평가≠SCI평가정보) · 별칭 4(SOL 시점, 상폐 상품 예시 등).

### 2-5. 어떻게 활용하나

1. **조건 추출·정규화**: 질의의 "타이거"·"곱버스"·"AA급"을 사전으로 표준 코드로 변환 → SQL 파라미터. 런타임 AI 추측 대신 사전 조회(결정적).
2. **커버리지 판정**: 센티널 목록(코드표·기초지수 사전)이 "확인할 수 없음" 판정의 근거.
3. **근거 표기**: 답변에 쓴 해석(예: "AA0은 AA로 해석")의 출처를 사전에서 인용 — 정성평가 '리스크 관리' 대응.

### 3-2. 수집 절차 (수집기 `collectors/collect_krx_etf_constituents.py`)

1. KRX 로그인 → 화면번호 `13108`(기본 통계 > 증권상품 > ETF > PDF) → [조회] → `F12 > Network > getJsonData.cmd` → Request Headers의 **Cookie 값 전체 복사** → `collectors/krx_cookie.txt`에 저장(**비밀값 — .gitignore 등록, 커밋 금지**).
2. 프로브(1종목으로 프로토콜 확인):
   ```bash
   python external_data/collectors/collect_krx_etf_constituents.py --probe --date 20260821
   ```
   내장 bld 후보를 순회해 유효 JSON을 주는 코드를 자동 채택한다(8/13 실측: `dbms/MDC/STAT/standard/MDCSTAT05001` 첫 후보 유효). 응답 컬럼: 종목코드·ISIN·시장·증권그룹·종목명·CU당 수량·평가금액·구성금액·구성비중(%).
3. 전량 수집(요청 간 1초 대기, 약 25~30분):
   ```bash
   python external_data/collectors/collect_krx_etf_constituents.py --all --date 20260821
   ```
   산출: `constituents/raw/<날짜>/*.json`(gitignore — 재생성 가능) + 통합 `constituents_<날짜>.csv` + 수집 메타(소스 URL·bld·파라미터·수집 시각 — 근거 표시 규정 대응).
4. 수집 후 `python kg/build_kg.py`로 그래프 재생성, `python storage/load_duckdb.py`로 표 재적재.

**세션 만료가 HTTP 400으로 나타난다(8/13 실측)**: 1초 간격 수집 중 약 25분 뒤부터 전부 400. 문서화된 만료 신호(`LOGOUT`)가 아니라 요청량 제한으로 오인하기 쉽다. 원인은 IP 차단이 아니라 **세션 만료** — 재로그인해 새 쿠키를 넣으면 즉시 정상. 수집기는 연속 실패 10회(`--max-consec-fail`)면 즉시 중단하고, 쿠키 갱신 후 같은 명령으로 이어받기(resume)한다. 8/28 재수집 때는 중간에 느려져 무버퍼 모드로 재시작했고 이어받기로 손실 0.

## 5. 결측 질의 대응 원칙

- 채점 기준은 제공 데이터(8/26 재배포본)다. 결측 필드 질의의 1차 답변은 항상 **"제공 데이터로 확인할 수 없음"** + 근거(어느 테이블·컬럼이 비어 있는지) 명시.
- 값이 0이거나 비어 있는 행은 주최 문답대로 순위·목록에서 제외하고 그 사실을 답변에 적는다.
- 사전(§2)은 결측을 "메꾸는" 게 아니라 **결측을 정확히 판별하고(센티널 인식) 있는 값을 정확히 해석하기 위한** 자산이다.
