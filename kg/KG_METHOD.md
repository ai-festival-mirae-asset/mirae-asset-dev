## 2. 왜 이 구조인가

- **온톨로지는 공식 형식(8/19)**: 주최 자료(과제 설명 p.9)가 `ontology/common.ttl·bond_kr.ttl·etf_kr.ttl·etf_gl.ttl·fund_pub.ttl` 5파일과 접두어 `fp:`·공통 상위 클래스 `fp:Product`·예시 선언(`fp:ForeignETF rdfs:subClassOf fp:ETF`)을 제시했다. 8/11~13 의 단일 `finance.ttl` 어휘를 그대로 계승해 5파일로 나누고, 국내/해외를 클래스로 갈랐다(`fp:DomesticETF·DomesticETN` / `fp:ForeignETF·ForeignETN`). 인스턴스는 **가장 구체적인 클래스 하나로만** 타이핑하고 상위(`fp:ETF`·`fp:Product`)는 온톨로지의 `rdfs:subClassOf` 로 추론되는 몫이다. 코드는 온톨로지에 선언된 항만 쓴다(테스트가 잠금).
- **저장소 중립(N-Triples)**: 표준 직렬화만 출력해 두면 어떤 그래프 저장소든 그대로 적재된다. `kg_store.py`(인메모리, 서버 기동 시 적재)가 현재 저장소이며, 제품 저장소 전환은 필요해질 때(§8.1 — 현재는 불필요 판단).
- **결측 = 트리플 미생성**: 값이 없는 것은 없는 것으로 둔다. 해외ETF에 위험등급 트리플이 없는 것 자체가 "확인할 수 없음" 답변의 근거다(가드레일 §3). 온톨로지도 같은 말을 한다 — `etf_gl.ttl` 은 해외ETP 에 `fp:riskGrade` 최대 개수 0 제한(owl:Restriction)을 선언한다.
- **제약은 두 겹으로 검사**: ① `build_kg.py`가 적재 전에 코드로 검사하고 위반을 `build_report.json`에 집계한다(위험등급 1~6, ETF/ETN disjoint, 9999 센티널 등). ② 같은 규칙을 `ontology/shapes.ttl` 에 SHACL 로 선언해 두고 `kg/validate_shacl.py`(pyshacl)로 독립 재검사한다 — 8/18 기술세션의 "SHACL 검증" 강조에 대응. 서버 실행에는 ②가 필요 없다(오프라인·테스트 전용).
- **결정적**: 타임스탬프 등 휘발 값을 출력에 넣지 않고 수치는 원문 lexical 보존 — 같은 입력이면 같은 출력(전처리 파이프라인과 동일 원칙).
- **파일 자기완결**: 각 `.nt`는 참조하는 회사·지수 노드의 타입·라벨을 포함해 단독 적재 가능. 파일 간 중복 트리플은 RDF 집합 의미상 무해.
- **옛 어휘 파일 방어**: 8/18 이전(`mf:` 네임스페이스)에 만든 `kg/output/*.nt` 를 새 코드가 적재하면 그래프 채널이 조용히 "상품 없음"으로 오답할 수 있어, `kg_store` 가 첫 줄에서 옛 네임스페이스를 발견하면 "재생성 필요" 오류로 즉시 멈춘다.

## 6. 구축 중 발견 — 국내ETF 운용사 컬럼 오염 (8/11 발견 → **8/13 복구 완료**)

`cu_fund_mgmt_co`(운용사)에 회사명이 아니라 **상품명 전체(공백 없는 형태)가 들어간 행 54건 + 브랜드 결합값("한화PLUS"·"미래에셋TIGER"·"삼성KODEX") 10건** = 오염 64행 실측.

- 해외ETF의 유사 의심 건은 실제 사명("First Trust Advisors LP" 등)으로 확인 — 오염 아님.

### 7-3. 1순위 — 별칭 통합 (8/22 구현)

**문제(실측)**: 회사·지수 노드는 원시 표기 기준이라 "미래에셋"(국내ETF 원천)과 "미래에셋자산운용"이 별개 노드였다 — 역관계 질문("미래에셋자산운용이 굴리는 상품 전부")이 갈라진다. 해외 종목은 ISIN으로 통합했지만 한글명이 없어 "캠브리콘 담은 ETF"를 한글로 물으면 이름 색인이 CAMBRICON을 못 잇는다. 운용사 표기 오염 64행(§6)처럼 표기 변형이 실제 사고를 낸 전력이 있다.

**설계(원칙 — 복구만 하고 병합하지 않는다)**: ① `common.ttl`에 SKOS 어휘 선언 — 정식 이름은 `rdfs:label`, 별칭·약칭·한글명은 `skos:altLabel`(노드는 합치지 않는다. "삼성"과 "삼성액티브"는 별개 법인 — 8/13 결정 유지). ② `build_kg.py`가 별칭 사전(`alias_dictionary.csv`)·운용사 복구표·해외 종목 한글명(`constituent_aliases.csv`)에서 altLabel 트리플을 생성(이름표 218개 → 8/28 빌드 233개). ③ `kg_store`의 회사·종목 검색이 label+altLabel을 한 색인으로 보고, 같은 별칭이 여러 노드에 걸리면 **합집합으로 답하고 표기 차이를 근거에 남긴다**. ④ 검증: 정식명 역관계 질의·한글 별칭 질의 시험 + SHACL 위반 0.

**왜 1순위였나**: 외부 문헌의 공통 병목(개체 연결 재현율)과 우리 실측 빈틈이 정확히 겹치는 자리다. 온톨로지 어휘 자체의 발전(SKOS 표준 도입)이라 "온톨로지 활용" 채점 항목에도 직접 기여하고, 기술제안서에 "표준 어휘로 별칭을 선언하고 병합 대신 합집합"이라는 설명 가능한 설계 이야기가 생긴다. 8/28에는 같은 원리로 지수 정규화 사전(`base_index.csv`)의 동의어('코스피200' 한글 표기 등)를 개체 색인에 승격했다.

### 7-4. 2순위 — 국내 벡터 확장 (8/22 구현, 전제 정정 포함) + 채권·펀드 임베딩은 만들지 않기로

벡터 인덱스는 원래 **해외 ETF 전략 서술만** 담고 있었다. 국내 상품은 이름·사전 일치에만 의존해 테마 사전에 없는 새 주제("양자컴퓨팅" 유형의 다음 신조어)에 안전망이 없었다.

**전제 정정(구현 중 실측)**: 국내 `cu_strtegy`는 서술문이 아니라 **분류값 4종**(실물복제·합성복제·액티브·C)이었다 — 해외와 컬럼명만 같고 내용이 다르다. 분류값을 임베딩하면 한 텍스트에 상품 수백 개가 매달려 검색이 오염된다. → 국내는 **정식명·약칭·기초지수로 합성한 문장**을 임베딩한다(`vector/build_index.py`, 8/27 재배포본 기준 국내 합성 1,779건 + 해외 서술 6,026건 = 고유 7,723건). 이름 속 테마 어휘("2차전지", "로봇")가 뜻으로 검색되고 한↔영 교차 성질도 이름에 적용된다. 시장을 명시한 질문에는 벡터 결과에 시장 필터를 건다.

**채권·공모펀드 임베딩 — 안 만든다(실측 근거)**: 채권 52컬럼에는 자유 서술 컬럼이 0개, 펀드 `*_desc` 7개는 전부 최대 12자 분류값(투자지역 7종 등). 임베딩이 이기는 대상은 **자유 서술문**이고, 분류값은 SQL 필터가 결정적으로(오차 0으로) 처리하는데 임베딩하면 비슷한 분류값끼리 잘못 뭉치는 소음만 생긴다. 재검토 조건: 주최가 투자설명서 같은 비정형 문서를 추가 제공할 때.

### 7-5. 남은 후속 (전부 마감 전 착수하지 않음 — 제안서 "확장성" 서술)

1. `fp:subsidiaryOf` — 공정위 계열사 데이터 확보 후 3단 순회(자회사→편입→운용사) 완성. 그전까지 회사명 접두 근사 + 해석 명시.
2. ETF-of-ETF 편입분(EF 341행)의 상품 간 관계(`fp:holdsProduct`)와 그룹 관계.
3. 해외 상장 ETF 마스터(6,037종)의 구성종목 — SEC N-PORT.
4. 테마 개념의 SKOS 분류 체계 승격(현재는 테마 사전 + 의미 검색).
