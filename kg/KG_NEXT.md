# 지식그래프·온톨로지 발전 연구 — 무엇을 다음에 키울 것인가 (8/22)

> **이 문서는**: 지식그래프(점·선 지도)와 온톨로지(어휘 규칙집)의 성능을 더 높일 방법을
> 내부 실측(우리 데이터의 알려진 빈틈)과 외부 연구(2025~26 그래프 질의응답 문헌)에서
> 조사해 순위를 매긴 연구 기록이다. 구현 전 검토용 — 결정되면 PLAN.md 에 옮긴다.
> 모르는 용어는 [GLOSSARY.md](../GLOSSARY.md), 현재 구조는 [KG_METHOD.md](KG_METHOD.md).

## 1. 조사 방법

- **내부**: KG_METHOD.md §6~7 의 알려진 빈틈 + 8/19 성적표에서 그래프 채널이 어떤 질문을
  못 받았는지 역추적 + DuckDB 실측(아래 수치).
- **외부**: 그래프 기반 질의응답(GraphRAG 계열) 최근 문헌 조사. 공통 결론 두 가지 —
  ① 질문 속 이름을 그래프 노드에 정확히 잇는 **개체 연결(entity linking)의 재현율**이
  전체 정답률의 최대 병목이다(같은 대상의 표기 변형·약칭·오타가 주범).
  ② 문서 덩어리 대신 **그래프의 노드·간선(부분그래프)을 근거로 회수**하면 여러 단계
  연결 질문(multi-hop)에서 정확도가 오른다 — 우리 구조(그래프 채널 → 근거 → 생성기)와
  같은 방향이라, 발전은 "새 구조 도입"이 아니라 **연결 데이터의 폭을 넓히는 쪽**이 맞다.

## 3. 최우선 추천 — 별칭 통합 (skos:altLabel) — **8/22 구현 완료**

> 구현: `ontology/common.ttl` §0(skos 선언) + `kg/build_kg.py`(별칭 사전 2종 → 이름표 218개)
> + `kg/kg_store.py all_names` + `kg/query_kg.py`(회사·종목 대조를 정식명+별칭으로).
> 검증: 정식명 CQ2 질의·"캠브리콘" 그래프 질의 성공, 테스트 +3(합계 39).

**문제(실측)**: 회사·지수 노드는 원시 표기 기준이다. 그래서
- "미래에셋"(국내ETF 원천)과 "미래에셋자산운용"은 **별개 노드** — 역관계 질문
  ("미래에셋자산운용이 굴리는 상품 전부")을 그래프 단독으로 풀면 목록이 갈라진다.
- 해외 종목은 ISIN 으로 통합했지만 **한글명이 없다** — "캠브리콘 담은 ETF"를 한글로
  물으면 이름 색인이 CAMBRICON 을 못 잇는다(현재는 검색 계층 보정에 의존).
- 운용사 표기 오염 64행(8/13 복구)처럼 **표기 변형이 실제 사고를 낸 전력**이 있다.

**설계(원칙 유지 — 복구만 하고 병합하지 않는다)**:
1. 온톨로지: `common.ttl` 에 SKOS 어휘 도입 선언 — 정식 이름은 `rdfs:label`,
   별칭·약칭·한글명은 `skos:altLabel` (노드 자체는 합치지 않는다. "삼성"과
   "삼성액티브"는 별개 법인 — 8/13 결정 유지).
2. 생성: `build_kg.py` 가 별칭 사전(`alias_dictionary.csv`)과 운용사 복구표
   (`mgmt_resolution.py`)에서 altLabel 트리플을 추가 생성. 해외 종목은
   한글명→영문 매핑을 사전에 보태는 것부터(수집분 상위 보유 종목 우선).
3. 질의: `kg_store` 의 상품·회사 검색이 label + altLabel 을 한 색인으로 보고,
   같은 별칭이 여러 노드에 걸리면 **합집합으로 답하고 표기 차이를 근거에 남긴다**.
4. 검증: CQ2 역관계 실측(미래에셋 계열 표기 3종이 같은 목록을 내는지) +
   한글 별칭 질의 테스트 + SHACL(altLabel 은 검사 제약 없음 — 추가만이라 회귀 위험 낮음).

**왜 1위인가**: 외부 문헌의 공통 병목(개체 연결 재현율)과 우리 실측 빈틈이 정확히
겹치는 자리다. 온톨로지 어휘 자체의 발전(SKOS 표준 도입)이라 "온톨로지 활용" 채점
항목에도 직접 기여하고, 기술제안서에 "표준 어휘로 별칭을 선언하고 병합 대신 합집합"
이라는 설명 가능한 설계 이야기가 생긴다.

## 4. 2순위 — 국내 ETF 벡터 확장 (8/22 구현 — 전제 정정 포함)

현재 벡터 인덱스는 **해외 ETF 전략 서술만**(5,638건) 담고 있다.
효과: 테마 사전에 없는 새 주제("양자컴퓨팅" 유형의 다음 신조어)가 실전에 나왔을 때
국내 상품 쪽 안전망이 생긴다(현재는 이름·사전 일치에만 의존).

**전제 정정(8/22 구현 중 실측)**: 처음 조사에서 "국내 `cu_strtegy` 1,579행이 채워져
있다"고 썼는데, 값을 열어 보니 **서술문이 아니라 분류값 4종**(실물복제 745 ·
C 409 · 액티브 343 · 합성복제 82)이었다 — 해외와 **컬럼명만 같고 내용이 다르다**.
분류값을 임베딩하면 한 텍스트에 상품 수백 개가 매달려 검색이 오염된다.
→ 채택안: 국내는 **정식명 · 약칭 · 기초지수(있는 58건)로 합성한 문장**을 임베딩한다
(`vector/build_index.py kr_synth_text`). 이름 속 테마 어휘("2차전지", "로봇")가
뜻으로 검색되고, 한↔영 교차("미국 소형주"→Small Cap 0.63 실증) 성질도 이름에 적용된다.
분류값 4건의 기존 임베딩은 인덱스 조립에서 제외한다(코퍼스 밖 벡터 미포함 규칙).

## 4-2. 채권·공모펀드 임베딩 — 만들지 않기로 결정 (8/22 실측 근거)

같은 질문("다른 상품군에도 임베딩을 만들어야 하나?")을 채권·펀드에 대해 조사했다.

| 상품군 | 서술문 후보 | 실측 | 결정 |
|---|---|---|---|
| 국내채권 (52컬럼) | 없음 | 이름·코드·숫자뿐 — 자유 서술 컬럼 0개 | **안 만든다** |
| 공모펀드 (47컬럼) | `*_desc` 7개 | 전부 **최대 12자 분류값**(투자지역 7종 · "배당/이자" · "공모/사모" 등) | **안 만든다** |

이유: 임베딩(의미 검색)이 이기는 대상은 **자유 서술문**이다 — 같은 뜻을 다른 말로
쓴 글을 찾아 주는 기술이라서다. 분류값은 이미 SQL 필터가 결정적으로(오차 0으로)
처리하는데, 임베딩하면 비슷한 분류값끼리 잘못 뭉치는 소음만 생긴다. 이름 검색은
키워드 색인+별칭 사전이 담당(§3). **재검토 조건**: 주최가 펀드 투자설명서 등
비정형 문서를 추가 제공하면 그때 그 문서를 임베딩한다(채권도 동일).
