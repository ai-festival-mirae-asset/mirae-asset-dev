## 1. 한눈에 보기 (핵심)

**무엇을 했나:** 원본 xlsx 4종을 읽어 ① 문자열·타입 오염을 청소하고 ② 무의미한 센티널 값을 NULL로 통일하고 ③ 해석이 필요한 값(신용등급, 위험등급, 상품유형, 상장·만기 상태 등)을 `drv_*` 파생 컬럼으로 표준화한 CSV 4종을 만들었다. 비정상 행은 공모펀드 1건 + 국내ETP 1건, 총 2건을 격리했다.

**왜 했나:** 이 데이터는 그냥 적재하면 **틀린 답을 만드는 함정**이 6종류 있다 — 숫자로 저장된 날짜, 공백 40칸짜리 "값", 결측이 아닌 척하는 센티널 문자열, 컬럼이 밀린 행, NULL의 의미가 'N'인 플래그 컬럼, 표기가 오염된 등급명. 전처리의 목적은 값을 예쁘게 만드는 게 아니라 **"있는 값은 정확히 계산되고, 없는 값은 정확히 없다고 판정되게"** 만드는 것이다. (평가 항목에 '확인할 수 없음' 명시가 있으므로 결측 판별력이 곧 점수다.)

**3대 원칙**

1. **원본 보존** — 원본 컬럼은 지우거나 덮어쓰지 않고(전량 무정보 컬럼 제외), 해석값은 `drv_*` 접두어 파생 컬럼으로 추가한다. 원본 대조가 항상 가능하다.
2. **결측은 메꾸지 않고 판별한다** — 센티널→NULL 변환은 하되, NULL을 다른 값으로 채우지 않는다. 0 대체·평균 대체 금지.
3. **모든 규칙은 기록된다** — 규칙ID·대상 컬럼·영향 행수가 [`processed/preprocessing_report.csv`](processed/preprocessing_report.csv)에 남는다(79건). "왜 이 값이 바뀌었지?"는 리포트에서 역추적한다.

## 3. 왜 이렇게 했는가 — 함정별 상세

### 3-1. 숫자로 저장된 날짜 (채권 R5)

`ISU_DT`·`MAT_DT`·`CRD_GRD_DT`·`PD_STD_INFO_UPDATE`가 `double precision`이다(`20260330.0`). 이대로 적재하면 "잔존만기 3년 이내" 같은 날짜 연산이 전부 불가능하다. ISO 문자열(`2026-03-30`)로 변환했고, 값 0·8자리 미달은 파싱 불가로 NULL 처리 후 리포트에 남겼다. `MAT_DT=99991231`은 날짜가 아니라 **영구채 표기**이므로 날짜는 유지하되 `drv_is_perpetual='Y'`로 분리 표시했다 — 이 플래그 없이 잔존만기를 계산하면 영구채가 "잔존 7,973년"으로 랭킹을 오염시킨다.

### 3-2. 결측이 아닌 척하는 값들 (R2·R3·R6·R16·R21)

이 데이터의 결측은 세 가지 얼굴로 온다: ① 진짜 NULL, ② 공백 40칸 문자열(국내ETF `cu_base_index` 1,551건), ③ 의미 없는 센티널 값(`'000'`, `'NULL'` 문자열 18,416건, 20자리 0, **해외ETF 기초지수의 "Index is not provided by Management Company" 류 2,705건 = 48%**). ②③을 NULL로 통일하지 않으면 `WHERE cu_base_index IS NULL`이 통하지 않아 **"확인할 수 없음"이라고 답해야 할 질의에 쓰레기 값으로 답하게 된다.** 특히 해외ETF 기초지수는 "결측 0%"로 보이지만 실질결측 48%였다 — 센티널 인식이 없으면 커버리지 판정 자체가 틀린다.

### 3-3. 컬럼 밀림 행 (공모펀드 R20)

Excel 84,563행은 컬럼이 한 칸씩 밀려 `itm_no='"'`, `exchdg_yn='00080008'`, `zrin_fd_ivst_risk_gcd='00020054'`가 된 비정상 레코드다. 값 프로파일링에서 발견된 이상값 3종이 전부 이 **한 행**에서 나온 것을 격리 후 확인했다. 도메인 규칙(itm_no 12자리 형식, exchdg_yn∈{Y,N}, 위험등급∈{1..6})을 위반하는 행을 자동 탐지해 `quarantine_*.csv`로 분리한다 — 특정 행 번호 하드코딩이 아니라 규칙 기반이므로 원본이 갱신돼도 동작한다.

### 3-4. NULL의 의미가 'N'인 플래그 컬럼 (해외ETF R18)

`cu_etn_yn`·`cu_inverse_short_yn`은 값이 있으면 전부 'Y'다(각 59건·171건). 이런 컬럼의 NULL은 결측이 아니라 **'N'**이다. 그런데 이 해석을 쿼리 작성자마다 따로 하게 두면 실수가 난다. 원본은 그대로 두고 `drv_is_etn`·`drv_is_inverse`에 Y/N을 명시적으로 채웠다. (반례: 해외ETF `wu_core_yn`은 관측값이 N뿐이라 같은 규칙을 적용할 수 없어 제외 — 컬럼마다 관측 분포를 보고 판단해야 한다.)

### 3-5. 신용등급·위험등급의 표준화 (R9·R10·R11·R14·R23)

- `CRD_GRD`의 `AA0`은 AA와 다른 등급이 아니라 **무부호(플랫) 표기**다(관측 분포와 신평 3사 공식 기호체계로 확인). 정규화 없이 "AA 이상" 필터를 걸면 AA0 1,713건이 누락된다. `drv_crd_grd_rank`(AAA=1~D=20)로 서열 비교를 SQL로 만들었다 — "AA 이상"=rank≤3.
- `PD_EVCO_CRD_GRD`("AAA, AAA, AA+")는 복수 평가사 등급 병기다. 개수·최저등급을 분해했고, 스플릿(평가사 불일치) 시 보수적으로 최저등급을 쓰는 실무 관행을 따랐다.
- 위험등급은 상품군마다 표기가 다르다(`PD_RISK_GCD_11` vs `1` vs 코드 0 포함). 전 상품군 공통 `drv_risk_grade`(1=매우 높은 위험 ~ 6=매우 낮은 위험)로 통일했다. 채권 0(58건)은 미분류이므로 NULL. **주의: "위험등급이 낮다" = 숫자가 크다(5~6등급).** 등급명 문자열은 표기 오염('높은위험'/'높은 위험')이 있어 코드 기준 파생만 신뢰한다.
